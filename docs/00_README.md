# CampusSchedule / 校园课表助手

> 面向高校学生的学期课程表应用。首个适配学校：广东轻工职业技术大学（GDIPU）。

## 1. 项目目标

做一个可以从学校现有教务系统中导入个人学期课表，并在本地提供更好课表体验的应用。

首版目标：

1. 用户不需要把学校账号密码交给本应用。
2. 用户自己在学校官方页面完成统一身份认证。
3. 导入器只读取“已经登录后的课表页面”中的课程数据。
4. 将学校原始数据转换为统一课程模型。
5. 支持周课表、学期切换、当前周、课程详情、提醒、ICS 导出。
6. 数据默认只保存在用户设备本地。
7. 架构允许后续增加其他高校 Adapter。

## 2. 推荐产品形态

采用“两部分”架构：

- `CampusSchedule Web/PWA`
  - React + TypeScript
  - 负责课表展示、课程管理、提醒设置、学期管理、导入导出。
- `CampusSchedule Importer`
  - Chromium 浏览器扩展，Manifest V3
  - 在用户已经登录的学校教务系统页面中运行。
  - 识别课表页面，读取 DOM 或页面已加载的数据。
  - 不读取、不保存用户名、密码、验证码。

为什么不直接在普通网页里抓取教务系统：

- 浏览器同源策略/CORS 会阻止普通 PWA 直接读取另一个域的登录态页面。
- 学校可能有统一身份认证、验证码、二次认证、风控。
- 把学校密码保存到第三方应用既不必要，也会显著增加安全风险。
- 浏览器扩展能够在用户主动访问并登录的教务页面中执行受限解析。

## 3. 广东轻工职业技术大学首版适配

当前已确认：

- 学校官网存在“智慧3.0”入口。
- 官方站点存在教务系统入口。
- 学校教务系统设计材料明确包含学生端“学期课表查询”。

当前没有在公开网页中确认：

- 2026 年实际学生课表页面的 DOM 结构。
- 当前课表查询 API 的 URL、参数及返回结构。
- 当前系统是否仍使用历史教务系统的所有页面结构。

因此：

**GDIPU Adapter 不允许凭猜测写死接口。**

开发阶段必须使用以下任一真实数据来源：

1. 用户登录后课表页面的 DOM Snapshot；
2. 用户登录后导出的 HTML；
3. 用户在开发者工具中保存的课表接口响应样例（删除个人敏感字段后）；
4. Agent 通过浏览器扩展在用户当前页面中只读探测 DOM。

## 5. MVP 完成定义

以下全部通过才算 MVP 完成：

- 可以安装 PWA。
- 可以安装扩展。
- 用户主动打开学校教务系统并自行登录。
- 扩展可以识别“课表页面”。
- 可以解析至少一份真实 GDIPU 学期课表。
- 课程名称、教师、地点、星期、节次、周次正确。
- 单双周/离散周次不会被错误展开。
- Web 端能够显示“本周”和“学期总课表”。
- 刷新页面后数据仍存在。
- 可以重新导入并进行差异更新。
- 可以导出 ICS。
- 不保存学校密码、验证码、认证 Cookie。
- 对未知页面结构不会静默产生错误课表，而是明确报“适配器无法识别”。

## 6. 非目标

首版不做：

- 自动破解验证码。
- 模拟用户账号密码登录。
- 批量抓取其他学生信息。
- 绕过学校权限。
- 修改学校教务系统数据。
- 抢课/自动选课。
- 成绩爬取。
- 云端保存学校账号密码。
